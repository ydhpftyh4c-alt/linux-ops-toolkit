# Linux Ops Toolkit

Учебный CLI для задач начинающего системного администратора: диагностика диска, памяти, systemd-служб и TCP-портов; резервное копирование файлов с SHA-256 и проверяемое восстановление. Python 3.12+, стандартная библиотека, без pip-зависимостей.

## Запуск

```sh
python3 -m opskit health --path / --service nginx --tcp 127.0.0.1 80
python3 -m opskit health --path / --json --output health.json
```

Linux используется для `/proc/meminfo` и systemd. Для Windows/macOS есть ограниченный режим `python -m opskit health --skip-memory --path .`; systemd-проверки там не поддерживаются. В Windows `py -3` заменяет `python3`.

Проверки только читают состояние системы. TCP-проверки выполняйте на своих серверах; CLI не сканирует диапазоны. Запросы к systemd выполняются без shell, с ограничением времени и валидацией имени unit. При недоступной метрике выводится UNKNOWN, а не выдуманное значение.

| Код завершения | Значение |
|---|---|
| 0 | Все проверки OK |
| 1 | Есть WARNING |
| 2 | Есть CRITICAL |
| 3 | Есть UNKNOWN или ошибка параметров/операции |

Если есть несколько состояний, возвращается максимальный код. По умолчанию WARNING начинается с 85% использования диска/памяти, CRITICAL с 95%; границы включены. Память считается через MemAvailable, поэтому файловый кэш не приравнивается целиком к занятой памяти.

## Резервное копирование и восстановление

```sh
# source-dir уже существует; backup.zip должен находиться за его пределами.
python3 -m opskit backup create ./source-dir ./backup.zip
python3 -m opskit backup verify ./backup.zip
python3 -m opskit backup restore ./backup.zip ./restored-dir
```

`restored-dir` не должен существовать. Копия сначала проверяется и распаковывается в отдельный staging-каталог. Итоговый каталог создаётся после успешной проверки файлов. Перезапись существующего архива/каталога не допускается. Для архива используется эксклюзивное создание файла. Аварийное завершение процесса во время копирования может оставить неполный ZIP; команда `verify` обнаружит это.

Защиты: SHA-256 и размер каждого файла, предел 1 GiB и 10 000 файлов, ограничение размера manifest, проверка путей и состава архива, запрет симлинков и Windows junctions. Код не вызывает `extractall`. Параметр `--max-bytes` меняет предел размера. SHA-256 обнаруживает случайное повреждение, но не удостоверяет автора архива: manifest не подписан.

Ограничения: копируются содержимое и относительные пути обычных файлов. Пустые каталоги, ACL, владельцы, права, xattrs и открытые базы данных не сохраняются. Источник не блокируется; для согласованного снимка изменяемого приложения сначала остановите запись или используйте snapshot. При ошибке финального переноса возможен неполный итоговый каталог: он сохраняется для диагностики. Это не замена полноценной системе резервного копирования.

## Проверка проекта

```sh
python3 -m unittest discover -s tests -v
bash -n scripts/healthcheck.sh
```

CI проверяет Python 3.12/3.13 на Linux и Windows. Тесты покрывают границы порогов, разбор MemAvailable, ошибки systemd, TCP-проверку, backup/restore, повреждение checksum, traversal, неожиданные элементы архива и запрет перезаписи. Примеры unit/timer лежат в `examples/`; они не устанавливаются автоматически.

## Практические задания

1. Создать тестовые конфиги, сделать backup, изменить исходники и восстановить копию в новый каталог. Сравнить SHA-256.
2. Запустить health-check в Linux VM и объяснить каждое поле отчёта.
3. Настроить systemd timer вручную после проверки путей и создания пользователя `opskit`.
4. Добавить новую проверку с тестами, например срок действия TLS-сертификата.
5. Подписать manifest и добавить политику хранения копий как отдельное изменение.

[Разбор для собеседования и runbook](docs/runbook.md).

Проект учебный, не подтверждает production-эксплуатацию. Код и документация подготовлены с помощью AI-ассистента; перед использованием в портфолио стоит пройти сценарии запуска и восстановления самостоятельно.
